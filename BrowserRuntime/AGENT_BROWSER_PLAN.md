# Agent browser upgrade plan (2026-10-09)

Goal: close the capability gap with Claude in Chrome while keeping the isolated
Chrome for Testing profile, per-chat executors and the no-replay contract.

## Reference: what Claude in Chrome does

Studied from the installed extension (`fcoeoabgfenejglbffodgkkbkcdhcgfn`, v1.0.100,
minified bundle; behaviour only, no code reused):

- MV3 extension with the `debugger` permission drives the user's real Chrome over
  CDP; Claude Code talks to it through a native-messaging host. One tab group per
  session.
- Perception, chosen by the model per step:
  - `read_page`: own accessibility-tree generator injected into all frames at
    `document_start`; stable `ref_N` ids (WeakMap), `filter: interactive`, depth
    limit, focus on one ref, 50 000-character cap, password/card values redacted;
  - `get_page_text`: main article text;
  - screenshots (`Page.captureScreenshot`, JPEG, resized to a known size so
    model coordinates map back exactly) plus `zoom`;
  - `find`: natural-language element search answered by Haiku over the tree.
- One `computer` tool: click/double/triple/right click, type, key, scroll,
  scroll_to, hover, drag, wait, by ref or by coordinates, dispatched as trusted
  input (`Input.dispatchMouseEvent` / `Input.dispatchKeyEvent`). Works on canvas,
  custom widgets, shadow DOM and iframes.
- Extras: `javascript_tool`, console and network reading, file upload, tabs,
  resize, GIF recording.
- Safety: per-domain permissions, plan approval, sensitive-field redaction. No
  per-action verify round-trip: the next observation is the check.

## Current gaps in Context Desk

- Only 7 upstream actions (`server.py` `browser_action`); no scroll, hover, drag,
  coordinates, JS evaluation, dialogs or waiting.
- No visual channel: the model never receives a screenshot.
- `browser_snapshot` read mode has no element refs and skips frames;
  `interactive` returns the full upstream accessibility tree (slow, unfiltered).
- Every action needs a caller-made `actionID`, `expectedURL` and a separate
  `browser_verify` call: 2–3 tool calls per step.
- `browser_cards` needs model-written CSS selectors.

Note: pinned Chrome DevTools MCP 1.10.1 already ships `take_screenshot`, `hover`,
`drag`, `click_at` (behind `--experimentalVision`), `evaluate_script`, `wait_for`
and `handle_dialog`. Its screenshots do not report a coordinate mapping, so the
visual channel uses our own CDP capture.

## Invariants kept in every stage

- Isolated Chrome for Testing profile; cookie import rules unchanged.
- A durable action record precedes every dispatch; an uncertain transport
  outcome stops the executor; nothing is replayed automatically.
- Page content (text, tree, screenshots) is data, never instructions.
- Bounded outputs (characters, nodes, image size) with explicit truncation notes.
- Russian and English tool descriptions and user-facing errors.
- Existing tools keep working until a replacement is verified.

## Stage 1 — Visual channel and free-form input (delivered 2026-10-09, 2c98234)

1. `cdp.py`: minimal CDP client over the verified loopback endpoint (WebSocket
   framing, fragmentation, size caps, per-call deadlines). Attaches only to the
   owned page target recorded at `browser_open`; never to other targets.
2. `browser_screenshot`: viewport JPEG via `Page.captureScreenshot` with a clip
   scale so the image is at most 1280×1280 (below client downscaling limits).
   Returns MCP `image` content plus `{width, height, cssWidth, cssHeight, scale}`.
   Must not focus or unhide the browser (check background-tab capture; use
   focus emulation if frames stall).
3. `browser_input` (mutating, journaled like `browser_action`, `actionID`
   generated by the server when omitted): `click`, `double_click`,
   `right_click`, `hover`, `drag`, `scroll`, `key`, `type`, `wait`, targeted by
   screenshot coordinates (mapped back through `scale`) or by uid. Trusted CDP
   input events. Returns the new URL/title and, optionally, a fresh screenshot.
4. Server/broker: pass image content through IPC and MCP responses.
5. Verify image delivery end to end for Codex app-server and Claude Code.

Acceptance: model completes a canvas/custom-widget task and an infinite-scroll
list by screenshots and coordinates; hidden browser stays hidden; no-replay tests
cover the new tool; unit tests for coordinate mapping and WebSocket framing.

## Stage 2 — Page model with stable refs (delivered 2026-10-09)

Delivered as `browser_read` (`mode: tree | text`, `filter`, `ref`, `depth`, `maxChars`) next to
the legacy `browser_snapshot`, plus `ref`/`toRef`, `scroll_to` and `select` in `browser_input`.
Covered elements are refused (except hover/scroll/type); refs live in the page main world.

1. `page_tree.js`: injected generator modelled on the reference behaviour:
   roles/names, `ref_N` ids kept in a page-side WeakMap across calls,
   `interactive` filter, depth limit, focus on one ref, character cap with
   truncation note, password/one-time-code/card values redacted, open shadow
   roots, same-origin iframes.
2. `browser_read` replaces `browser_snapshot` read mode: `mode: tree | text`
   (`text` = main-content extraction), returns refs usable by `browser_input`.
3. Ref resolution: page script returns the element's viewport box; the action
   scrolls it into view and clicks its centre with trusted input. Stale refs fail
   with a clear error instead of guessing.

Acceptance: refs survive a React re-render on the benchmark pages; `interactive`
tree for a large page stays under the cap; read latency below the current
`interactive` snapshot.

## Stage 3 — One-call steps (delivered 2026-10-09)

Delivered: settling (navigation, network with long-request cut-off, DOM mutations
excluding inline style) bounded by `settle`; `changes` diff by ref or new-page head;
risk classes submit/navigation/dialog (expectedURL required only for them); dialogs
reported and answered (`action=dialog`) through a persistent per-tab CDP session;
new tabs reported and a hidden browser kept hidden; refs never reused across
documents. `browser_action`/`browser_verify` stay for compatibility.

1. `browser_input` returns a compact observation after each action (URL, title,
   dialog state, focused element, small interactive-tree diff; screenshot on
   request) so a separate verify call is optional.
2. Risk classes: submitting forms, Enter in a form, uploads and cross-origin
   navigation require `expectedURL` and keep the explicit verification guidance;
   plain reads, scrolls, hovers and in-page clicks do not.
3. Update tool descriptions and server instructions (ru/en); keep
   `browser_action`/`browser_verify` for compatibility one release, then retire.

Acceptance: benchmark workflows (`workflow_benchmark.py`) need fewer tool calls
per step than the current baseline with no lost no-replay guarantees.

## Stage 4 — Hard pages and diagnostics

- Cross-origin iframes via `Target.setAutoAttach` (flattened sessions) for tree,
  input and screenshots.
- `browser_eval`: bounded JavaScript evaluation with serialized, capped results
  (mutating, journaled).
- Dialog handling, file upload by ref (existing workspace scope rules), console
  and network summaries for the owned tab.

## Deferred / optional

- `find` by natural language through a small model (needs model access from the
  runtime; cost and privacy review first).
- Retiring the Chrome DevTools MCP dependency once all tools run on `cdp.py`.
- Real-Chrome mode through an own extension (conflicts with the isolation
  principle; only on explicit user decision).

## Measurement

Baseline before Stage 1 with `benchmark.py`/`workflow_benchmark.py`: success,
tool calls per task, response bytes, latency. Re-run after each stage and record
results in `docs/improvements.md`.
