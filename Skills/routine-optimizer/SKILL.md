# Routine optimizer

Use this optimization pass when creating recurring work. Understand its goal, expected frequency, variable inputs, required coverage, permissions and observable completion criteria. Inspect existing relevant workflows and available tools before adding a new recipe.

Look for repeated reads, reusable evidence, compact tool responses, unnecessary full-page reads, batching and earlier exact-match checks. Choose improvements that fit this routine; keeping the straightforward approach is valid when savings do not justify added complexity. Keep site selectors and domain decisions in separately editable resources. Change platform code only for a missing general capability.

Write a reusable workflow with applicability conditions, recommended steps, alternatives when assumptions fail, and completion checks. Preserve mandatory source coverage and qualification rules. Label untested ideas as hypotheses. Where measurement is warranted, compare equivalent task results and coverage alongside actual available latency and token metrics. Response bytes are not token counts.

Represent recurring intent separately from activation: a workflow can be used on demand, and a routine definition can describe a proposed schedule without enabling it. Honor any existing user authorization to create or activate routines using an available, supported scheduler. Context Desk's scheduled-job viewer is read-only; do not write `~/.codex/automations` or install another scheduler through this skill. Report a scheduling limitation without claiming an active routine.

Keep output proportional to the task: the recipe, selected improvements, assumptions and actual validation results. Future run evidence can improve the recipe; preserve its goal and permissions rather than treating one observed case as a universal rule.
